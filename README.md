# ELZYN — متجر جاهز للنشر على GitHub + Vercel

متجر ELZYN (واجهة المتجر + لوحة الإدارة + API) — نسخة مُصحَّحة تصلح للنشر على Vercel مباشرة من غير ما تقع بـ `500 FUNCTION_INVOCATION_FAILED`.

## إيه اللي كان بيحصل قبل كده (سبب خطأ 500)؟

النسخة القديمة كانت بتعمل اتصال بـ Upstash Redis أول ما الدالة تشتغل على Vercel، ولو الاتصال فشل — متغيرات ناقصة أو غلط، أو Upstash واقع مؤقتًا — **الدالة كلها كانت بتهنج وكل طلب في الموقع بيرجع `500 FUNCTION_INVOCATION_FAILED`** (صفحة "This page is unavailable").

### إيه اللي اتصلّح؟

- الموقع **مش بيقع تاني مهما يحصل**: لو Upstash مش متاح بيشغل بالبيانات المحفوظة آخر مرة (مرآة محلية) أو البيانات الافتراضية، والصفحة الأساسية والمنتجات بيظهروا عادي.
- لو Upstash رجع يشتغل، الحفظ **بيرجع يشتغل لوحده** من غير ما تعمل Deploy تاني.
- أي حفظ فاشل وقت القطع بيرجع برسالة عربية واضحة (`تعذّر الحفظ، جرّب تاني`) بدل صفحة الخطأ.
- `/admin` كانت بتطلع 404 على Vercel — اتصلّحت (تحويل لـ `/admin.html` من الـ CDN).
- حد الطلبات كان بياخد IP داخلي واحد لكل الزوار على Vercel — اتصلّح (بيقرا IP الزائر الحقيقي تلقائيًا).
- إضافة `/ping` و `/api/health` للتأكد إن كل حاجة شغالة بعد النشر.

## التشغيل محليًا

يتطلب Node.js 18 أو أحدث.

```bash
node server.js
```

افتح `http://localhost:3000` — الإدارة على `/admin`. عند أول تشغيل بدون `ADMIN_PASSWORD` تتولد كلمة سر عشوائية وتظهر في الطرفية.

## خطوات النشر من الصفر (GitHub ثم Vercel)

### 1) ارفع المشروع على GitHub

فك ضغط الملف، وبعدين:

- **من موقع GitHub:** اعمل Repository جديد (بدون README) → اضغط *uploading an existing file* → **اسحب كل محتويات المجلد** (مش المجلد نفسه) في خانة الرفع → Commit.
  - مهم: ملف `vercel.json` ومجلد `api` وملفه `api/[...route].js` لازم يترفعوا **بأسمائهم زي ما هما بالظبط** — متغيرش أسماء الملفات.
- **أو بالأوامر** (لو عندك Git):

```bash
cd elzyn
git init
git add -A
git commit -m "ELZYN store"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

### 2) اربطه بـ Vercel

1. من [vercel.com](https://vercel.com) اضغط **Add New → Project** واختار مستودع GitHub بتاعك.
2. **Framework Preset: Other** (بيتحدد لوحده من `vercel.json`) — سيب كل إعدادات البناء فاضية، المشروع مش محتاج Build.
3. اضغط **Deploy** — الموقع هيشتغل على طول حتى من غير أي متغيرات (لكن البيانات هتبقى مؤقتة، شوف الخطوة اللي بعدها).

### 3) متغيرات البيئة (مهمة للبيانات الدائمة)

من **Settings → Environment Variables** في المشروع على Vercel ضيف:

| المتغير | القيمة |
| --- | --- |
| `UPSTASH_REDIS_REST_URL` | من [upstash.com](https://upstash.com) → Create Database → تبويب **REST API** → انسخ `UPSTASH_REDIS_REST_URL` |
| `UPSTASH_REDIS_REST_TOKEN` | من نفس الصفحة → `UPSTASH_REDIS_REST_TOKEN` |
| `ADMIN_PASSWORD` | كلمة سر قوية للوحة التحكم `/admin` |

- الخطة المجانية في Upstash كفاية جدًا للمتجر.
- **مهم جدًا:** بعد إضافة المتغيرات روح **Deployments → أحدث نشر → النقاط الثلاثة ⋯ → Redeploy** — المتغيرات مش بتشتغل غير بعد إعادة النشر.

### 4) اتأكد إن كل حاجة تمام

- `https://موقعك.vercel.app/ping` → لازم يطلع `ok`
- `https://موقعك.vercel.app/api/health` → لو `"storage":"upstash"` يبقى Upstash متظبط صح (لو `"tmp"` يبقى المتغيرات ناقصة، ولو `"redis-down"` يبقى فيهم غلط)
- جرّب طلب من المتجر وسجّل دخول `/admin` بكلمة السر بتاعتك

## التخزين

- **مع Upstash (المُوصى به):** المنتجات والطلبات والإعدادات والصور المرفوعة بتتحفظ دائمًا وبتفضل موجودة مع كل تشغيل جديد.
- **من غير Upstash:** الموقع يشتغل عادي بس البيانات مؤقتة (بترجع للافتراضي مع كل تشغيل بارد للسيرفر) — استخدمه للتجرية بس.
- **لو Upstash وقع مؤقتًا:** الموقع بيفضل شغال للزوار بالبيانات المحفوظة، والحفظ بيرجع لوحده أول ما الخدمة ترجع.

## المسارات

- `/` واجهة المتجر
- `/admin` لوحة الإدارة (كلمة السر من `ADMIN_PASSWORD`)
- `/api/*` واجهة API — `/ping` و `/api/health` للتشخيص

## ملاحظات أمنية

- متترفعش `.env` ولا أي مفاتيح على GitHub (ملف `.gitignore` مستعد للكده).
- كلمة السر بتتخزن متشفرة (scrypt) وجلسات الإدارة موقّعة بـ HMAC.
